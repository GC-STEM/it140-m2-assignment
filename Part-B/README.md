# Part B | IDE Features Reflection

**Assignment progress:** [0 Start Here](../README.md) → [1 Part A](../Part-A/README.md) → **2 Part B** → [3 Submit](../README.md)

## Overview

In Part B, you will reflect on your experience using an integrated development environment (IDE) while completing the `name_age` program in Part A.

You will identify **three IDE features** that helped make your work easier or more effective and explain why those features are useful to programmers.

Use the notes and observations you made while completing Part A. Focus on features you **actually used or observed** while reviewing documents, writing code, finding problems, running your program, or testing it.

If you are unsure what a feature is officially called, use Microsoft's documentation to confirm its name:

* [Visual Studio Code Documentation](https://code.visualstudio.com/docs) — general VS Code features and tools
* [Editing Python in Visual Studio Code](https://code.visualstudio.com/docs/python/editing) — Python-specific editing features

## Deliverable

**Part B produces one deliverable:** your completed IDE Features Reflection.

Use the provided [`ide_features.md`](./ide_features.md) starter file to write your reflection.

**Do not submit it yet.** After completing Part B, return to the assignment [Start Here](../README.md) page for instructions to submit both Part A and Part B deliverables in D2L Brightspace.

## What You Will Do

### 1. Review Your Part A Experience

Before writing, think about the IDE features you noticed while completing the `name_age` program.

Review any notes you made during Part A and consider features that helped you:

* Read or navigate files
* Understand Python code
* Write or format code
* Recognize Python syntax
* Find errors or warnings
* Run commands or programs
* Test or debug your program
* Organize your work

Choose **three features that you personally found useful**.

Your reflection should explain your own experience rather than simply provide definitions of IDE features.

If you do not know the official name of something you used, check:

* [Visual Studio Code Documentation](https://code.visualstudio.com/docs)
* [Editing Python in Visual Studio Code](https://code.visualstudio.com/docs/python/editing)

Use Microsoft's name for the feature in your reflection.

### 2. Write the Introduction

In `ide_features.md`, find:

```md
## Introduction
```

Replace the starter text below that heading with a brief introduction.

Your introduction should:

* Identify the IDE you used for this assignment.
* Briefly explain why you used that IDE.
* Connect your IDE experience to your work on the `name_age.py` program.

Keep the introduction concise. The three feature sections are the main focus of the reflection.

### 3. Complete Feature 1

Find:

```md
## Feature 1 – Name of Feature1
```

Replace `Name of Feature1` with **Microsoft's name for the IDE feature** you are discussing.

Use the [Visual Studio Code Documentation](https://code.visualstudio.com/docs) or [Editing Python in Visual Studio Code](https://code.visualstudio.com/docs/python/editing) to confirm the feature name if needed.

Then replace the starter text below the heading with one paragraph that:

1. Identifies the feature.
2. Explains what the feature does.
3. Describes how it helped you while completing Part A.
4. Gives a specific example from your own experience.
5. Explains how the feature made programming easier or more effective.

For example, think about what you were trying to accomplish when you used the feature and what the feature helped you do.

Do not simply state that a feature was "helpful." Explain **how and why** it helped.

### 4. Complete Feature 2

```md
## Feature 2 – Name of Feature2
```

Use the [Visual Studio Code Documentation](https://code.visualstudio.com/docs) or [Editing Python in Visual Studio Code](https://code.visualstudio.com/docs/python/editing) to confirm the feature name if needed.

Then write one paragraph that:

1. Explains what the feature does.
2. Describes how you used or observed it while completing Part A.
3. Explains how it improved your work.
4. Discusses why the feature could be useful to a beginning programmer.

Use a specific example from your own experience whenever possible.

### 5. Complete Feature 3

Find:

```md
## Feature 3 – Name of Feature3
```

Replace `Name of Feature3` with Microsoft's name for a **third IDE feature**.

Use the [Visual Studio Code Documentation](https://code.visualstudio.com/docs) or [Editing Python in Visual Studio Code](https://code.visualstudio.com/docs/python/editing) to confirm the feature name if needed.

Then write one paragraph that:

1. Identifies and explains the feature.
2. Describes how it supported your work on the `name_age` program.
3. Gives a specific example of how you used or observed it.
4. Explains how the feature supported effective programming.

For example, a feature might have helped with readability, organization, writing code, identifying problems, running the program, or testing.

### 6. Write the Conclusion

Find:

```md
## Conclusion
```

Replace the starter text with a brief conclusion.

Your conclusion should:

* Summarize what you learned from using the IDE.
* Reflect on how IDE features affected your programming experience.
* Explain how the features you identified could help you in future programming work.

Do not introduce a new feature in the conclusion. Use it to bring together the ideas you already discussed.

### 7. Add References if Needed

The `## References` section is for sources that you actually used while completing your reflection.

Microsoft's documentation is the preferred source for confirming the official name of a VS Code feature or learning more about how it works:

* [Visual Studio Code Documentation](https://code.visualstudio.com/docs)
* [Editing Python in Visual Studio Code](https://code.visualstudio.com/docs/python/editing)

If you use an outside source:

1. Cite or acknowledge the source where appropriate in your reflection.
2. Add an APA-style reference under `## References`.
3. Include applicable sources such as official documentation, websites, AI tools, chats, or agents that contributed to your work.

Your reflection should still describe **your own experience**. A source can help you identify or explain a feature, but it should not replace your personal observations.

If you do **not** use outside sources, delete the `## References` heading and its starter text.

For additional citation examples and guidance, see the [Module Two Assignment Wiki](https://github.com/GC-STEM/it140-m2-assignment/wiki).
